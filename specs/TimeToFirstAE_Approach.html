Time to First Adverse Event

Proposed kri0019 / cou0019  ·  site- and country-level  ·  two-sided flagging

Flag sites whose subjects go unexpectedly long — or unexpectedly short — before their first adverse event is recorded, relative to the rest of the study.

Why this isn't kri0001

kri0001 measures AE volume per day on study. It is blind to onset timing. A site can post a study-average AE rate across the full window while recording nothing for its first three months.

SignalDirectionPlausible cause
Long time to AElow hazard Delayed AE identification or data entry; under-reporting at early visits; staff untrained at activation
Short time to AEhigh hazard Over-reporting / miscoded non-AEs; sicker baseline population; medical history logged as AE

Both tails are actionable, so this flags two-sided — the same Threshold: -2,-1,2,3 pattern kri0001 already uses.

Definition

Subject level
  • t_ref = firstparticipantdate
  • Has an AE → days_at_risk = min(aest_dt) − t_ref, event = 1
  • No AE → days_at_risk = timeonstudy, event = 0 (censored)
Site level
  • Numerator = subjects with a first AE
  • Denominator = ∑ days at risk
  • Model = Analyze_Poisson
  • Score = adjusted z-score
Censoring is the crux. Averaging "days to first AE" over only the subjects who had an AE is badly biased — a site with short follow-up would look like it has a long time to AE. Every enrolled subject must contribute time at risk, censored or not.
Why Poisson, not survival code. Poisson regression on person-time is the standard equivalent of an exponential time-to-event model. That means this metric drops straight into the existing gsm pipeline with zero new statistics code — and the double-programming QC test can verify it against a real survival fit.

Pipeline

Mapped_AE + Mapped_SUBJ→ Input_TimeToEvent ⬥ NEW→ Transform_Rate→ Analyze_Poisson→ Flag→ Summarize
new function — one, and it's metric-agnostic existing gsm.core, unchanged

No gsm.mapping changes needed. AE.yaml already maps aest_dt; SUBJ.yaml already maps firstparticipantdate and timeonstudy.

gsm.core::Input_TimeToEvent() returns the standard Analysis_Input shape and is reusable for any future time-to-event KRI — time to first query, first lab, discontinuation.

Open decision: which way does the score point?

The Poisson score sits on the hazard scale, so its sign is inverted relative to the metric's name:

  • Unexpectedly long time to AE → low hazard → negative z
  • Unexpectedly short time to AE → high hazard → positive z

That is consistent with the rest of gsm, where negative means under-reporting and carries the heaviest risk weight. Recommendation keep the hazard scale and document it in a report footnote, rather than negating the score and reversing RiskScoreWeight. But reviewers will read "Time to…" and expect the other direction, so this needs an explicit call.

Open questions

  1. Metric ID. kri0016 is claimed by two open issues (#231 Duplicate Weight and #258 IP Non-Starters), and kri0017/kri0018 by #232. kri0019 is proposed here, but ID assignment needs an owner.
  2. Reference date. firstparticipantdate (captures pre-dose AEs) or firstdosedate (the more meaningful zero for treatment-emergent AEs)? Enrollment for Phase 1, configurable in the workflow.
  3. AE scope. All AEs, or serious (aeser) / grade ≥3 (aetoxgr) only? All for Phase 1; a serious-only variant is a cheap follow-on reusing the same helper.
  4. Accrual gate. Person-days alone could pass a site with one long-follow-up subject. Consider a secondary minimum subject count. All thresholds are placeholders pending calibration on pilot studies.

Edge cases the unit tests must cover

  • AE start date before the reference date → clamp to zero or drop; decide and test
  • Missing aest_dt → subject stays at risk (censored); document the bias
  • timeonstudy = 0 → excluded from the denominator
  • A site where no subject has an AE → must yield a valid negative score, not NA
  • Multiple AEs on the same day → a single first event

Reporting

Phase 1 reuses Visualize_Scatter with Analyze_Poisson_PredictBounds — x = person-days at risk, y = observed first-AE count. No new widget.

Phase 2 (optional) a Kaplan–Meier overlay, site vs study, would communicate this metric far better than a scatter. Any new widget must be built on gsm.vizr — the vendored gsm.viz bundle is being retired (#288, #291).
